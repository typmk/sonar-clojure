Why is this an issue?

A function obtains attacker-influenced data and passes it toward a dangerous sink through one or more calls.

This is an over-approximation: it does not track argument positions, so a function that both obtains such data and calls a sink is reported even when the two are unrelated. Confirm the path before acting.

How can I fix it?

Validate or escape the value at the boundary where it enters.
