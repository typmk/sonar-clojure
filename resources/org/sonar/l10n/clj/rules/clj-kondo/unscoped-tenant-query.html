Why is this an issue?

A query that names no owner or tenant returns rows from every tenant. Whether that is a bug depends on what is being queried, which is why this rule is off by default and is a sweep aid rather than a gate.

What it is worth

Measured against 39,307 lines of Clojure across three repositories:

  • 124 findings before tuning; a hand-classified sample of 14 held roughly 10 that were not tenancy bugs.
  • 56 after excluding pull (an entity id the caller already holds is not a scan — 40 of the 124) and queries touching only the shared taxonomy and compat layer.
  • A second sample of 12 still held roughly 8 that were not bugs: a token revocation list that is global by design, the lookup of an organisation by slug (which is the tenant lookup), and bootstrap queries.

So precision is somewhere near a third, hand-estimated from samples rather than measured against ground truth. That is useful for an audit sweep — "show me every unscoped scan so I can read them" — and nowhere near good enough to fail a build. Enabling it in a quality profile would produce dozens of issues most of which are correct code.

Why it cannot be much better

Deciding whether a query should be tenant-scoped needs to know which entities are tenanted in the domain model, and admin surfaces legitimately query across tenants. Shape alone cannot tell an authorisation bug from a deliberate cross-tenant read.

How can I fix it?

If the query should be scoped, put the scope in the query rather than filtering afterwards — a filter applied later still reads every tenant's rows. If it should not be scoped, the query is correct and this finding is noise.
